# Copier 1.0 breaker pass

**Run:** November 15, 2026, on the code at 658822a (task #540)
**Breaker:** independent agent, read-only on the repo, proof tests in a scratch folder
**Result:** 2 high, 6 medium, 9 low. Each claim that depends on site data was checked against Nikhil's live data (counts only) before fixing. Each fix has a unit test that fails on 658822a and passes now. A second independent agent then reviewed the fixes (1 high, 4 medium, 6 low), and a third reviewed the changes made after that (1 high, 1 medium, 6 low); both rounds are at the end. 126 tests pass, and every bug the three agents demonstrated with a proof test is gone when their proofs are rerun.

## High

### H1. The screen rule could swap in the wrong branch and still say complete
- **Where:** `core/model.js` letters and matchesScreen, leafOnScreen in `platforms/claude.js` and `platforms/chatgpt.js`
- **Problem:** The export's text keeps list numbers ("1. Fly"); the page's innerText does not (checked live in Chrome: an ordered list reads "Take the train\nFly"). A reply ending in a numbered list therefore failed to match its own rendering. The rule then accepted any other leaf whose ending appeared in the screen text, such as a stopped first try that matches the reply's opening line, and exported it with a note saying it followed the screen.
- **Answer:** Fixed. letters() drops list numbers and task boxes from the export's text (not from page text, see the second round). One shared pickOnScreen() decides for both adapters: it switches only to a single matching leaf, never to one whose ending also appears in the data's leaf, and never when two leaves match. Tests: ordered list matches its rendering, stopped first try kept out (Claude and ChatGPT), ambiguous match ignored.

### H2. Claude's older file list dropped a second file with the same name
- **Where:** `platforms/claude.js`, the older file list merge
- **Problem:** The merge keyed on the base name. An upload "budget.xlsx" plus Claude's edited "outputs/budget.xlsx" lost the output file while the header said all files were downloaded, and a later entry could overwrite the upload's fallback path.
- **Answer:** Fixed. A message file pairs with a list entry only when the name and the side (uploads or outputs) match, and takes one fallback at most; every other entry is its own file. On 40 live chats no chat had the same name twice, so today's exports do not change. Test added.

## Medium

### M1. A reply still streaming, stopped or failed was not flagged
- **Problem:** Spec 8.2 asks for a note on a last turn in progress. No adapter read the flags.
- **Answer:** Fixed with notes, which the spec asks for, rather than "may be partial": the export holds everything the site stored. Values checked live: Claude stop_reason on 3,405 replies (user_canceled 13, error 4, truncated never true), ChatGPT status on 1,382 replies (in_progress 2, finished_partial_completion 1). Claude notes user_canceled, error, max_tokens and truncated; ChatGPT notes in_progress and finished_partial_completion; Grok notes partial or a non-empty inflightResponses. Copilot keeps the longest text seen for each position, and reads the page twice a moment apart before scrolling: text that grew means a reply is still being written, which gets the same note. Tests for every adapter.

### M2. ChatGPT sources footnotes could delete a space from the answer
- **Problem:** Checked live: all 111 sources_footnote entries have whitespace-only matched text, 11 of them zero-length. For those, the text search found the last space in the reply and removed it.
- **Answer:** Fixed. Whitespace-only references are never searched for and remove nothing; they stay in reading order so source numbers do not move. Test added.

### M3. Claude attachments held as extracted text kept their binary name
- **Problem:** Claude keeps only the extracted text of an attachment such as "Q3 report.docx"; saved under that name, the file would not open.
- **Answer:** Fixed. The saved file gets ".txt" when its name has no text extension ("Q3 report.docx.txt"); the export still shows the original name. Test added.

### M4. Cancel was mostly ignored
- **Problem:** The cancel flag was read only inside the file loop. Cancel while reading, with no files, or while building the ZIP still saved the file, and a popup Copy still reached the clipboard. A stalled download could not be cancelled.
- **Answer:** Fixed. The flag is checked after reading, after the files and after the ZIP is built; reading, each download and the ZIP build end within a quarter second of Cancel; the popup ignores anything from a cancelled run, including one cancelled while still connecting; Copy and Download from the page show Cancel in their progress note. Tests load the real content.js with a fake adapter.

### M5. Two runs could start at once
- **Answer:** Fixed. One run per page; a second click, popup or retry is told "Copier is already working on this page.", and from the page that note offers "Cancel it" (for a run whose popup closed). After a Cancel the lock is held one more second so Copilot can finish scrolling back. Tests added.

### M6. A failure of Claude's older file list was silent
- **Problem:** Any failure returned an empty list.
- **Answer:** Fixed. Checked live: 404 is the normal answer for a chat without the list (22 of 40 chats, the other 18 returned the list). A 404 stays silent; any other failure adds a note. Test added.

## Low

- **L1. A Claude citation marker could land inside a code fence.** Fixed: backticks are counted on the marker's own line only, and a marker inside a fenced block moves to after its closing fence. Test added.
- **L2. One message could break the rest of the file.** Fixed: an unclosed code fence in a reply is closed, and a line that opens an HTML comment outside code is escaped. ChatGPT code parts use a fence longer than any backtick run inside. Tests added.
- **L3. File names.** Links into the ZIP encode "#" and "%" (names keep them; "Invoice #12.pdf" is a valid name everywhere). After the length cap a name without an extension loses a trailing dot or space. Windows reserved stems are caught before the first dot ("nul.tar.gz"). Direction control characters are removed. Tests added.
- **L4. Copilot scroll position was not restored after Cancel or an error.** Fixed with try and finally; checked live.
- **L5. A Copilot total that changes is only noted.** Not changed. Positions were absolute in every live run, including the forced 14-message window. The note stays, and the untested list names a 100+ message Copilot chat.
- **L6. Copilot converted every visible message on every scroll step.** Fixed: a position already held is read again only when its text grew.
- **L7. Gemini images were retried for nothing.** Fixed: the error is marked final, and final errors are not retried. Test added.
- **L8. Gemini might export the wrong draft.** Fixed: the candidate whose id equals t[3][3] is exported, with the first candidate as the fallback. Checked live: t[3][3] equals the first candidate's id on 21 of 21 turns, so today's exports do not change. Test added.
- **L9. Other speculative items.**
  - Grok's address pointing at an older reply: already handled. The export notes when later replies exist past the reply in the address, and the screen check notes a mismatch.
  - Popup Copy over Chrome's 64 MiB message limit: fixed, the page answers "too large to copy from the toolbar, use Download".
  - ChatGPT supporting_websites: present on 0 of 1,382 live replies; not added. Claude citations carrying only sources[]: not seen live (129 sources placed); not changed.
  - Signed URLs in dumps of unknown content: fixed, a URL whose query looks signed loses its query. Test added.
