## Findings and fixes

1. **Copilot user messages came out empty.** Each user message names two elements through `aria-labelledby`: the hidden "You said:" heading and the message text itself. Stripping every label left nothing. Fixed in fd0f7c8: a label is stripped only when text remains after it. On the live page, the new rule kept 51 characters of the first user message where the old rule kept 0. A unit test was added. The end-to-end rerun passed after a reload.
2. **ChatGPT refuses 10 images from a tool (HTTP 403).** The images came from `api_tool` output. The download endpoint refuses them with this conversation's id, with the source conversation's id (the chat is a branch of another) and with no id. The page draws none of them either. The export lists each one as "could not be downloaded: HTTP 403". No fix: the site does not serve them.
3. **One ChatGPT attachment failed with "Failed to fetch"** and downloaded on a second try. Fixed in fd0f7c8: one automatic retry after a network error. A refusal from the site (HTTP 4xx) stays final. Not forced live: the original failure was a one-off.
4. **A branch picked with the version arrows was not followed.** Claude's data kept pointing at the version that was on screen when the chat was opened. Spec 8.2 says the export follows the branch on screen. Fix: the content script reads the last message on screen before extraction. When the data's leaf has enough text to compare and does not match the screen, the Claude and ChatGPT adapters use the leaf whose text does match, and the export notes that. When nothing matches, nothing changes and the screen check note stays. 5 unit tests were added. The Claude case passed live after a reload.

5. **ChatGPT changed its page markup.** The screen check read `[data-message-author-role]`, which ChatGPT no longer renders (0 elements; each turn is now one `[data-turn-key]` element holding the prompt and the reply). The screen check and the branch rule were silently off on ChatGPT. Fixed: both forms are read. With the new selector, the last turn on screen matched the data's current message on 2 of 2 chats (checked in the page with the same comparison). Also, the comparison now ignores link targets and bare URLs, since the page shows a link's text only (unit test added). Rerun after a reload on a 106-message chat: a normal Download carries no screen note; a Download after the last turn's text was replaced in the page carries the "may differ" note, so the check runs in the extension.
